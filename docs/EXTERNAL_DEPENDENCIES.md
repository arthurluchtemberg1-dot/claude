# Dependências externas

Ações que só o responsável pelas contas pode executar. Nenhuma delas bloqueia os módulos independentes; cada uma bloqueia o nível de maturidade indicado. **Não envie segredos por mensagem**: configure-os em `.env` ou nos formulários protegidos do painel.

| ID | Dependência | Bloqueia | O que é necessário (ação exata) | Enquanto isso |
| --- | --- | --- | --- | --- |
| DEP-OFFICIAL-DOCS | Acesso à documentação oficial (developers.facebook.com, support.google.com, developers.google.com, ads.tiktok.com, supabase.com, docs.stripe.com, lowify.com.br) | Revalidar macros de URL, janelas/limites Meta, deduplicação navegador×servidor, rota Google | Liberar esses domínios na política de rede do ambiente (Claude Code na web → configuração do ambiente → acesso à rede) **ou** anexar os PDFs/páginas das documentações | Macros marcadas "a verificar"; hipóteses listadas nos manifestos |
| DEP-LOWIFY-SAMPLES | Payloads reais anonimizados da Lowify para `sale.pending`, `sale.paid` (com e sem order bump/upsell) e `sale.refunded` | Estado "Validado em sandbox/produção" do conector Lowify; T16/T18 | Fazer uma venda de teste autorizada apontando o webhook para um endpoint de teste e exportar os corpos recebidos (Diagnóstico → Recebimentos → Ver corpo), removendo dados pessoais | Normalização baseada no exemplo documentado v1.0.0 |
| DEP-LOWIFY-AUTH | Confirmação com a Lowify se há assinatura/segredo de webhook ou IPs de origem | R09-20 (autenticação forte) | Perguntar ao suporte Lowify (chat.lowify.com.br) se o webhook suporta assinatura HMAC, cabeçalho de segredo ou lista de IPs | Token opaco na URL + rotação |
| DEP-LOWIFY-TRACKING | Parâmetros aceitos no link do checkout Lowify e preservação em upsell; confirmação de que UTMs da URL do checkout chegam em `tracking.*` | R15-01, vínculo por token | Venda de teste com `?utm_term=teste|trk_…` no link do checkout e verificação do webhook recebido; perguntar à Lowify o tamanho máximo dos campos | UTMs devolvidas são usadas como origem declarada |
| DEP-LOWIFY-TZ | Fuso do campo `timestamp` e moeda | Precisão de horário/moeda | Confirmar com a Lowify | Configurável por conexão (padrão America/Sao_Paulo, BRL) |
| DEP-LOWIFY-EXPORT | Formato de exportação de vendas do painel Lowify | Conciliação (R10-16, R21-02) | Exportar um CSV de vendas (anonimizado) do painel Lowify | — |
| DEP-META-APP | App Meta (developers.facebook.com) com Facebook Login for Business, permissões `ads_read` (e `ads_management` se gestão for desejada), Pixel/dataset e token de sistema para CAPI; App Review/acesso avançado para contas de terceiros | E3 (leitura de campanhas/gastos), E4 (CAPI em produção), E6 | Criar app do tipo Business, configurar URL de callback `…/v1/oauth/meta/callback`, preencher `META_APP_ID`/`META_APP_SECRET` no `.env`; gerar token de sistema no Business Manager para o dataset e cadastrá-lo em Pixels (fica cifrado); obter `test_event_code` no Events Manager | Parser de insights e payload CAPI testados localmente contra servidor simulado; envio real desligado |
| DEP-META-DOCS | Revalidação: idade máxima de eventos web, limite de lote, janela e grafia de deduplicação (`eventID` × `event_id`) | R17-10, R17-15, T42 | Ver DEP-OFFICIAL-DOCS | Valores atuais tratados como hipóteses |
| DEP-GOOGLE-APP | Projeto Google Cloud, OAuth, developer token Google Ads; decisão Data Manager API × API legada | E5 (Google Ads, GA4), login Google | Criar projeto, tela de consentimento OAuth, credenciais; solicitar developer token; preencher `GOOGLE_*` | Catálogo marca "Bloqueado externamente" |
| DEP-TIKTOK-APP | App TikTok for Business aprovado | E5 (TikTok Ads/Events API) | Criar app e solicitar escopos de anunciante/eventos; preencher `TIKTOK_*` | — |
| DEP-WHATSAPP | Número e app na WhatsApp Business Platform (Cloud API) ou provedor autorizado | E7 | Configurar conta WABA, número verificado, webhook | — |
| DEP-AI | Provedor e chave de IA | E6 (Gestor IA) | Definir `AI_PROVIDER`/`AI_API_KEY` | IA exibida como indisponível |
| DEP-EMAIL | Provedor de e-mail transacional (SMTP ou API) | E-mails reais (verificação, reset, convites) em produção | Contratar provedor, configurar domínio (SPF/DKIM) e `SMTP_URL` | Transporte `log`/`file` apenas em desenvolvimento |
| DEP-BILLING | Provedor de cobrança da plataforma e decisões de preço/planos | E8 (assinatura do SaaS) | Definir provedor (ex.: Stripe) em modo sandbox e política comercial | Modo de uso interno disponível |
| DEP-HOSTING | Hospedagem (web, API, worker), PostgreSQL/Redis gerenciados, domínio e TLS | Homologação/produção, domínio de coleta próprio, CDN do SDK | Escolher provedores, criar bancos com os papéis `tracker_app`/`tracker_system`, definir segredos por ambiente | Execução local reproduzível |
| DEP-SUPABASE | Decisão de usar Supabase (banco/auth/storage) em produção | R05-02 completo | Criar projeto Supabase; aplicar migrações com o papel dono; decidir se autenticação migra para Supabase Auth (ver D-003) | PostgreSQL puro compatível |
| DEP-OBSERVABILITY | Destino de logs/métricas/erros | R05-09, R42-01 | Escolher serviço e configurar `ERROR_TRACKING_DSN` | Logs estruturados em stdout |
| DEP-STORES | Contas Apple/Google Play e certificados | Publicação do app nativo (E9) | Criar contas de desenvolvedor | PWA |
| DEP-LEGAL | Revisão jurídica de política de privacidade, termos e DPA; decisões de retenção | Lançamento comercial | Revisar as minutas quando produzidas | Minutas identificadas como rascunho |
